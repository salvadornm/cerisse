\section{Overview}

The IBM module is organized as a layered custom BVH stack integrated with AMReX.
The active geometry backend is the custom implementation in \texttt{bvh\_defs.h},
\texttt{bvh.h}, and \texttt{eib\_bvh.h}. Legacy CGAL material remains as reference
code in \texttt{eib\_cgal.h}, but the production IBM path is the BVH path.

\section{Primary Runtime Path}

\begin{enumerate}[nosep]
  \item \texttt{main.cpp}: calls \texttt{IBM::ib.init(\&amr)}.
  \item \texttt{eib\_t::init}: computes level metrics (\texttt{dx\_a}, \texttt{diag\_a}, \texttt{di\_a}) and calls \texttt{read\_geom()}.
  \item \texttt{read\_geom} (in \texttt{eib\_io.h}):
  \begin{itemize}[nosep]
    \item reads files from \texttt{ib.filename},
    \item builds \texttt{geom\_a[i]} and \texttt{bvh\_a[i]},
    \item constructs \texttt{inside\_t} for each geometry,
    \item builds flattened \texttt{SurfElem\_a}/\texttt{LocalFrame\_a} and \texttt{geom\_offsets}.
  \end{itemize}
  \item \texttt{computeMarkers}: classifies solid/ghost cells (GPU path available with AMReX ParallelFor).
  \item \texttt{initialiseGPs}: builds per-ghost-point geometric/interpolation metadata.
\end{enumerate}

\section{Notes on 2-D and 3-D}

\begin{itemize}[nosep]
  \item In 3-D, \texttt{InsideTesterView} uses BVH-guided ray/closest-point logic on triangle faces.
  \item In 2-D, \texttt{InsideTesterView} now supports BVH-accelerated polygon edge culling for inside/outside and boundary checks.
  \item Both dimensions share the same dataflow in \texttt{eib\_t}, with geometry-specific logic selected by \texttt{AMREX\_SPACEDIM}.
\end{itemize}
